# 模型来源、确认与独立验证

## 草稿确认流程

自然语言分析先生成结构化草稿。用户应检查员工、变量、单位、班次、供需、约束和目标是否忠实于原问题；草稿通过结构校验后，服务计算稳定摘要。确认时必须提交同一摘要，若内容有变化就要求重新校验和确认。

只有服务端签发且尚未使用的确认凭据可以触发求解。Agent 工具不应自行调用确认入口，也不能绕过状态门禁。

## 求解后验证

求解器报告可行或最优后，仍需使用独立领域 validator 重新计算业务约束和目标值：排班检查人数、技能和工时；线性规划检查变量域、约束余量和目标；网络流检查弧容量、节点守恒与总费用。

求解器状态与独立 validator 结果必须同时呈现。不可行、无界或不支持状态不应伪造变量值，也不能标记为通过验证。

## RAG 证据边界

检索到的知识可提供公式解释、适用条件和方法建议，但不是本题的员工数据、目标系数、容量或约束事实。所有引用都应保留来源 URI 与章节定位；知识卡中的数字只能作为带来源的参考假设，未经用户确认不得写入题目模型。
