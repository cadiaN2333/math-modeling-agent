# 本地运行与 DeepSeek 密钥配置

## 首次安装

在 PyCharm 打开的项目终端中确认当前目录为 `D:\Agent`，然后安装项目依赖：

```powershell
python -m pip install -e '.[dev,agent]'
```

这会安装本地数学优化依赖、测试依赖、OpenAI 兼容 SDK 和 `.env` 加载器。

## 填写密钥

项目根目录已有一个本地 `.env` 文件。只需在 PyCharm 项目文件树中打开它，在 `DEEPSEEK_API_KEY=` 后粘贴自己的 DeepSeek API Key 并保存。不要把密钥写进 Python 源码、README、命令行参数或提交到 Git。

`.env` 已被 `.gitignore` 排除；`.env.example` 是不含真实密钥的模板，可供其他开发环境参考。

## 运行

在 PyCharm 的项目终端中直接运行，不需要先执行 `set` 或 `$env:`：

```powershell
python -m math_modeling_agent.cli --request '安排员工班次：三名员工中林晓有急救技能，两个八小时班次每班至少一人，第一班需要一名急救员。'
```

程序会从项目根目录自动加载 `.env`。当前终端环境变量若已存在同名设置，会优先保留该值，不会被 `.env` 覆盖。

如需确认密钥是否加载，只输出状态、不显示密钥：

```powershell
python -c "import os; print('密钥已加载' if os.getenv('DEEPSEEK_API_KEY') else '未加载')"
```

## 当前支持范围

当前可求解三个领域：

- 员工排班：使用 OR-Tools CP-SAT，支持员工技能、工时上限和班次覆盖要求。
- 连续/混合整数单目标线性规划：变量域为 continuous、integer 或 binary；全连续模型使用 OR-Tools GLOP，含离散变量时使用 SCIP，并由独立 validator 检查变量域、目标值和线性约束。
- 整数单商品最小费用网络流：使用 OR-Tools SimpleMinCostFlow；节点供给为正、需求为负，路线有整数容量与整数单位费用；必须满足全部供需并最小化总费用。小数货币要精确换算到最小费用单位，例如 2.35 元/箱表示为 235 分/箱。

非线性、多目标、多商品流、最大流、允许部分满足需求的最小费用最大流、连续小数流量，以及带时间窗或车辆路径的运输问题，仍会标记为暂不支持，不会偷偷转换成其他问题求解。

可用下列生产计划例子验证 LP 管线：最大化 `40A + 30B`，满足 `2A + B <= 100`、`A + B <= 80`、`A >= 0`、`B >= 0`；期望解为 `A=20`、`B=60`、利润 `2600`。

可用下列运输例子验证最小费用流管线：W1、W2 分别供给 20、30 箱；S1、S2 分别需求 25、25 箱；路线 W1→S1（容量20、费用2）、W1→S2（容量20、费用4）、W2→S1（容量25、费用3）、W2→S2（容量30、费用1），费用单位为元/箱。期望最低总费用为 80 元，路线流量依次为 20、0、5、25 箱。

## 分层 Evals

先离线检查案例集结构，不调用 DeepSeek：

```powershell
python -m math_modeling_agent.evals
```

显式在线评测全部 12 个案例会逐条调用 DeepSeek 并消耗 API 配额，案例包含排班、连续 LP、整数 LP、可行/无解运输和仍不支持的多商品流：

```powershell
python -m math_modeling_agent.evals --live
```

建议先只运行单个案例确认配置和输出；例如评估仓库配送运输问题：

```powershell
python -m math_modeling_agent.evals --live --case-id minimum_cost_flow_warehouse_delivery
```

如需本地回归全部单元测试，可在 PyCharm 终端使用隔离临时目录（避免系统 TEMP 权限问题）：

```powershell
$testTemp = Join-Path (Resolve-Path .\.venv).Path ('pytest-tmp-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $testTemp | Out-Null
.\.venv\Scripts\python.exe -m pytest -p no:cacheprovider --basetemp $testTemp -q
```

报告只输出案例 ID、分析状态、求解/校验结果和失败项，不包含密钥或原始 API 响应。仓库配送可行案例期望输出 `OPTIMAL`、总费用 80 元并通过独立校验；整数生产案例应由 SCIP 求得最优整数解；容量不足案例期望 `INFEASIBLE`；多商品流仍预期为“不支持”。当前 Evals 共 12 个案例；在线模式逐例调用 DeepSeek。
